# 인스피언 코딩테스트 과제 — 요구사항 정리

> 원본: [inspien-assignment-v2.1.pptx](inspien-assignment-v2.1.pptx) (v2.1, 2026.10.27)
> 구현 스택: Java + Spring Boot

## 1. 배경

온라인 쇼핑몰 "토토"는 주문·회계·운송을 사람이 수기로 옮기고 있어 누락과 지연이 잦다.
인스피언(EAI 회사) 개발자로서 이 흐름을 자동화하는 **API 기반 연계 시스템**을 설계·구현한다.
구체적인 설계와 구현 방식은 지원자가 정한다.

## 2. 연계 인터페이스

담당자 대화(슬라이드 3)에서 뽑은 업무 4가지.

| # | 인터페이스 | 트리거 | 소스 → 타깃 | 설명 |
|---|---|---|---|---|
| IF-01 | 주문 수신 | 실시간 (REST 호출) | 주문 XML → `ORDER_TB` | 주문 XML을 받는 API를 만들어 쇼핑몰 DB에 자동 저장 |
| IF-02 | 영수증 전송 | 주문 저장 후 | `ORDER_TB` → FTP 파일 | 주문마다 영수증 파일을 만들어 FTP에 업로드 (회계팀이 가져감) |
| IF-03 | 배송 연계 | **주기 실행** (배치/스케줄러) | `ORDER_TB` → `SHIPMENT_TB` | 쇼핑몰 주문을 보고 운송회사 DB에 배송 정보 등록 |
| IF-04 | 처리 추적 | 전 구간 | — | 어떤 주문이 어디까지 처리됐고, 어느 단계에서 무엇이 잘못됐는지 확인 가능해야 함 |

## 3. 제공 환경

### 3.2 권한 제약

- **DB:** `SELECT`, `INSERT`, `UPDATE`만 가능 → `DELETE`·DDL 불가. 테이블 추가나 데이터 정리는 할 수 없음.
- **FTP:** 목록 조회와 신규 업로드만 가능. 다운로드·덮어쓰기·이름 변경·삭제 불가 → **파일명이 겹치면 안 됨**.
- **FTP 파일명:** 지원자 이름(한글) 포함 필수.

## 4. 접속 정보 수신 (선행 작업)

DB·FTP 접속 정보는 과제 API를 호출해서 받아야 한다.

1. **요청:** 과제 PPT 슬라이드 5의 URL로 HTTP Basic 인증(username/password는 PPT 참고) 호출.
   본문은 `NAME`, `PHONE_NUMBER`(`010-1234-5678` 형식), `E_MAIL`을 담은 JSON.
   PPT의 예시를 복사·붙여넣기하면 따옴표 글자가 깨지므로 직접 입력할 것.
2. **응답:**
   - `APPLICANT_KEY`: 지원자 키
   - `ORDER_TB_CONN`, `SHIPMENT_TB_CONN`, `FTP_CONN`: 암호화된 접속 정보
   - `SAMPLE_DATA`: Base64 인코딩된 **EUC-KR** XML 문자열 (주문 XML 샘플)
3. **복호화:** AES-128 / ECB / PKCS5Padding
   - Key = `SHA-1(휴대폰번호 문자열의 UTF-8 바이트)`의 앞 16바이트
   - 응답 문자열을 Base64 디코딩한 뒤 복호화

> 주의: 인증 정보와 복호화한 접속 정보는 Git에 올리지 않는다. 환경변수나 `.gitignore`된 설정 파일로 관리한다.

## 5. 제출·면접 조건

- 화면 없는 일반 애플리케이션이면 됨. 필요한 라이브러리만 사용 (웹 앱 플랫폼 등은 불필요).
- **제출:** Git 저장소 주소를 이메일로 제출. **작업 단위 커밋 내역 필요.** 마감일은 개별 공유.
- **화상 면접(15분):** 제출 코드 이해도, 설계 역량 확인.
- **임원 면접:**
  - 현장 CBT 30분 (정보처리기사 난이도)
  - 과제 소개 PPT (발표 15분 이내)
  - 시연: 노트북에서 프로그램 실행, DB 접속 후 데이터 조회(참여자명·당일 날짜 기준), FTP 접속 후 업로드 파일 확인

## 6. 설계 시 결정할 것 / 미확인 사항

| 항목 | 내용 |
|---|---|
| 주문 XML 구조 | `SAMPLE_DATA`를 받아봐야 확정. 헤더(주문자) + 상세(상품) 구조라면 `ORDER_TB`의 1행 = 주문 상품 1건으로 펼쳐야 할 가능성 |
| ORDER_ID 채번 | XML에 포함되는지, 시스템이 만들어야 하는지 샘플 확인 필요. 만든다면 `A001`~`Z999` 형식, APPLICANT_KEY 범위 안에서 중복 없이 |
| SHIPMENT_ID 채번 | 시스템이 생성. 형식 동일 |
| STATUS 값 | 예: 수신(`N`) → 배송 연계 완료(`Y`) 등. 배치가 미처리 건만 고르는 기준이 됨 |
| 영수증 파일 포맷 | 형식 자유 (txt/csv/xml 등). 파일명은 한글 이름 + 주문ID + 타임스탬프 등으로 유일성 보장 |
| 처리 추적 방법 | DB에 테이블을 만들 수 없으므로 `STATUS` 컬럼 + 애플리케이션 로그(단계별, 주문ID 키)로 추적 |
| 시연 시 "당일 날짜 기준 조회" | 테이블에 날짜 컬럼이 없음. 어떻게 조회할지 면접 전에 확인 필요 |
| 문자 인코딩 | 샘플 XML은 EUC-KR. API 입력 인코딩과 FTP 파일명 인코딩(한글) 처리 필요 |
| 트랜잭션·재처리 | DB 저장, FTP 업로드, 배송 등록 중 일부만 실패한 경우의 상태 처리와 재시도 |
| "웹 앱 플랫폼 불필요"와 IF-01 | IF-01은 REST API가 필요하므로 Spring Boot 내장 서버는 사용. UI는 만들지 않고 의존성은 최소로 |

## 7. 개발 환경

- Java 25 설치됨 (Spring Boot 3.x 기준이면 Java 21 툴체인도 고려)
- 전역 Gradle·Maven 없음 → Spring Initializr로 Gradle Wrapper 포함해 생성
- 예상 의존성: `spring-boot-starter-web`, `spring-boot-starter-jdbc`, Oracle JDBC(`ojdbc11`), Apache Commons Net(FTP), Jackson XML 또는 JAXB
